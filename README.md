## О проекте

**BabyName** — веб-приложение для совместного выбора имени ребёнка. Два человека подключаются к одной комнате с разных устройств, независимо оценивают варианты и постепенно сужают список до финальных кандидатов.

Здесь нет автоматического победителя и нет задачи угадать чужой вкус. Каждый участник проходит одни и те же этапы, принимает решения самостоятельно, а итоговое имя становится общим только после явного подтверждения обоими.

Проект задуман как простой и спокойный инструмент для важного семейного решения.

## Как это работает

### 1. Комната для двоих

Один участник создаёт комнату и отправляет партнёру ссылку или шестизначный код. После подключения второго человека выбор можно начинать.

### 2. Первое впечатление

Участники независимо просматривают имена и отмечают те, которые им нравятся. На этом этапе вариант проходит дальше, если понравился хотя бы одному из двоих.

### 3. Имя и отчество

Оставшиеся варианты рассматриваются вместе с отчеством. Правило отбора остаётся прежним: достаточно положительной оценки одного участника.

### 4. Ласковые формы

На следующем этапе важны уже не только полные имена, но и то, как они звучат в повседневной жизни. Дальше проходят варианты, которые понравились обоим.

### 5. Дополнительный отбор

Если после основных этапов список всё ещё слишком велик, приложение проводит дополнительные раунды. Если подходящих вариантов не осталось, можно повторить попытку, не теряя историю предыдущих ответов.

### 6. Финальное сравнение

Когда остаётся не более пяти имён, приложение формирует все уникальные пары. Каждый участник выбирает предпочтительный вариант в каждой паре независимо от партнёра.

### 7. Совместное решение

Рейтинг помогает увидеть предпочтения, но не выбирает имя за участников. Каждый отдельно подтверждает свой вариант. Общим решение становится только тогда, когда оба подтверждают одно и то же имя.

## Принципы проекта

- **Равное участие.** У каждого свой голос и собственный выбор.
- **Независимость ответов.** Ответы партнёра не раскрываются, пока оба не завершат этап.
- **Последовательность.** Следующий этап открывается после завершения текущего обоими участниками.
- **Сохранение прогресса.** Ответы и текущий этап хранятся в Supabase.
- **Осознанный финал.** Статистика показывает совпадения и различия, но не подменяет решение пары.
- **Безопасность записи.** Голоса и переходы между этапами выполняются через серверные RPC-функции Supabase.

## Технологии

| Часть | Технология |
|---|---|
| Интерфейс | HTML, CSS, JavaScript |
| База данных | Supabase / PostgreSQL |
| Авторизация | Supabase Auth, анонимные сессии |
| Обмен данными | Supabase JavaScript Client |
| Хостинг | Netlify |

Приложение не использует сборщик или frontend-фреймворк: браузер загружает HTML, CSS и JavaScript напрямую.

## Локальный запуск

Для запуска не требуется установка frontend-зависимостей.

1. Склонируйте репозиторий:

   ```bash
   git clone https://github.com/aether-me/BabyName.git
   cd BabyName
   ```

2. Откройте `index.html` через локальный статический сервер или настройте в IDE запуск статической страницы.

3. Убедитесь, что в `app.js` указаны URL вашего Supabase-проекта и его публичный **publishable key**.

Для работы приложения нужен настроенный Supabase-проект. Одного открытия HTML-файла недостаточно, если база данных и авторизация ещё не подготовлены.

## Настройка Supabase

1. Создайте проект Supabase.
2. Включите анонимную авторизацию в настройках **Authentication → Providers → Anonymous Sign-Ins**.
3. Подготовьте схему базы данных, применив необходимые SQL-миграции из `supabase/migrations/` в хронологическом порядке и с учётом уже применённых миграций.
4. Проверьте политики Row Level Security и доступ к RPC-функциям.
5. Укажите URL проекта и публичный publishable key в `app.js`.

**Важно:** в клиентском коде допустим только публичный publishable key. Никогда не помещайте в `app.js`, репозиторий или frontend-код `service_role` key, секретные ключи или пароли. Публичный ключ не заменяет настройку RLS: безопасность данных обеспечивается политиками доступа и серверными функциями.

SQL-файлы из `supabase/tests/` предназначены для проверок. Не запускайте повторно уже применённые миграции в рабочей базе без предварительной проверки состояния схемы.

## Публикация на Netlify

Проект является статическим сайтом.

1. Подключите GitHub-репозиторий `aether-me/BabyName` в Netlify.
2. Выберите ветку `main`.
3. Оставьте команду сборки пустой.
4. В качестве publish directory укажите корень проекта: `.`.
5. Запустите deploy.

После публикации проверьте создание комнаты, подключение второго участника и прохождение этапов с двух разных устройств.

## Проверка логики

Для запуска автоматических тестов требуется установленный Node.js.

Из корня проекта выполните:

```bash
node --test tests/selection-rules.test.js
```

Тесты проверяют правила прохождения этапов, повторные попытки, формирование финальных пар, защиту от повторной отправки, совместное подтверждение, каталог имён и отдельные контракты SQL-миграции.

## Развитие

BabyName создавался как небольшой семейный проект, но за его простой механикой стоит важная идея: решение должно принадлежать обоим.

Приложение не стремится заменить разговор, интуицию или чувства. Оно помогает услышать друг друга, увидеть предпочтения без давления и подойти к выбору чуть спокойнее.
